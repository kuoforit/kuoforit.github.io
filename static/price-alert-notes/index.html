Price Alert Field Notes

A Discord bot that lives in one channel. Anyone in the channel types /alert with a coin and a price; the bot watches Binance and pings that person once when the price is touched, then deletes the alert.

It runs on the same Raspberry Pi 5 as the volume alert, but works differently: the volume alert only sends through a webhook, while this bot also has to read commands, so it is a real bot with its own login.

Set a level, get pinged the first time it trades there, then the alert is gone.The whole contract

Commands

01 · only in #price-alert
CommandWhat it doesWho sees the reply
/alert symbol:LPT price:1.7Sets a one-shot alert. LPT and LPTUSDT both work; the symbol field autocompletes from Binance's live contract list.Everyone in the channel
/alertsLists every active alert: number, coin, direction, target, who set it, how long ago.Only you
/remove alert_id:3Deletes an alert. Autocomplete offers only the alerts you're allowed to remove.Everyone in the channel

What the bot answers

/alert symbol:LPT price:1.7

✅ Alert #12: LPTUSDT ⬆️ rises to 1.7 (now 1.62, +4.94%).
   I'll ping @you once, then remove it.
  • Direction is decided at set time. A target above the current price waits for price to rise to it; a target below waits for a fall.
  • Who can use it: anyone who can see #price-alert. Access is controlled with normal Discord channel permissions, not by the bot.
  • Who can remove: the person who set the alert, or anyone with Manage Messages in the channel.
  • Limits: 50 active alerts per person. A symbol that isn't a trading USDT-M perpetual, or a price that isn't a positive number, is rejected with a short explanation.
  • Used outside #price-alert, every command replies privately with a pointer to the right channel.

When an alert fires

02

The bot posts in #price-alert, mentions the person who set the alert, and attaches a card:

@you
🔔 LPTUSDT reached 1.7
   Target      1.7
   Last price  1.7004
   Set at      1.62 · 2h 13m ago
   Alert #12 · Binance USDT-M last price · removed after firing
  • The title links to the coin's Binance futures page. Green for an upward touch, red for a downward one.
  • The alert is marked fired and stops being watched. If price chops around 1.7 afterwards, nothing else is sent. To watch the level again, set a new alert.
  • Only the alert's owner is pinged; @everyone and role mentions are blocked.

Data flow

03 · one long-running process

Green: Discord. Blue: inside the Pi5. Orange: Binance.

Unlike the volume alert, this is one process that stays up. It holds two live connections: one to Discord's gateway, to receive commands, and one to Binance's WebSocket, to receive prices. There is no polling interval; price updates arrive as they happen.

Touch detection

04
At set time
1Fetch the current last price over REST. Target above it → direction up; below → down; equal → rejected as already there.
On every price push
2Up alerts fire when the 1-minute candle's high ≥ target. Down alerts fire when its low ≤ target.
3In the minute the alert was created, only the live price counts. That candle's high or low may come from before the alert existed.
4Candles that ended before the alert was created are ignored entirely.
After firing
5The alert is removed from memory and marked fired in the database before the message is sent, so two pushes in quick succession can't fire it twice.

Why use the candle's high and low rather than the latest price: pushes arrive about every 250 ms, and a fast wick can touch 1.7 and come back between two pushes. The running high and low of the minute still record it.

Binance price feed

05 · no API key
SourceUsed forWhen
GET /fapi/v1/exchangeInfoThe list of trading USDT-M perpetuals, for validation and autocompleteAt start; refreshed when an unknown symbol is entered
GET /fapi/v1/ticker/priceCurrent last price when an alert is setOnce per /alert
GET /fapi/v1/klines 1m ×10Catch-up after a reconnect: did price touch while disconnected?On each (re)connect
wss://fstream.binance.com/market/stream<coin>@kline_1m for coins with active alerts onlyAlways connected
  • Dynamic subscription. Setting the first alert on a coin sends SUBSCRIBE; when its last alert fires or is removed, UNSUBSCRIBE. Coins nobody is watching cost nothing.
  • Path matters. Kline streams are served under /market/. The older /ws/ path accepts the connection but never sends candle data, which looks exactly like being blocked.
  • Last price (the traded price, what charts show) is used, not mark price.
  • WebSocket pushes don't count against Binance's 2,400-per-minute REST weight, so this bot doesn't compete with the volume alert running on the same IP.

Creating the Discord bot

06 · ~5 minutes, free

1 · Application

  1. Open discord.com/developers/applications and sign in.
  2. New Application → name it (e.g. Price Alert) → accept the terms → Create.

2 · Make it private

  1. Installation → Install Link → set to None → Save.
  2. Bot → turn Public Bot off → Save. This stops other people from adding your bot to their servers.
Order matters. Turning Public Bot off while the install link is still "Discord Provided Link" fails with "Private application cannot have a default authorization link." Set the install link to None first.

3 · Token and intents

  1. On the Bot page, leave all three Privileged Gateway Intents off. Slash commands don't need to read message content.
  2. Reset Token → copy it. It is shown once.
The token is the bot's password. Whoever has it can log in as the bot. It belongs only in the Pi's .env. If it leaks, press Reset Token again; the old one stops working immediately.

4 · Invite it to your server

  1. OAuth2 → URL Generator.
  2. Scopes: bot and applications.commands.
  3. Bot permissions: View Channels, Send Messages, Embed Links.
  4. Open the generated URL, pick your server, Authorize. This works even though the default install link is off.

5 · Channel and IDs

  1. Create #price-alert. Whoever can see it can use the bot.
  2. User Settings → Advanced → turn on Developer Mode.
  3. Right-click the channel → Copy Channel ID. Right-click the server icon → Copy Server ID.

The server ID is used to register the commands to that one server, where they appear immediately. Global commands can take up to an hour to show up.

Pi5: files & service

~/price-alert-bot/.envBot token, server ID, channel ID, per-user limit. Mode 600.
~/price-alert-bot/alerts.dbSQLite. Every alert with its owner, symbol, target, direction, set price and time, and status: active, fired or removed.
~/price-alert-bot/venv/Python virtualenv with discord.py (which brings aiohttp, used for both Binance REST and WebSocket).
…/systemd/system/price-alert-bot.serviceType=simple, Restart=always, RestartSec=10, enabled at boot, runs as a normal user.

Deploying

Source lives on the laptop in a local git repo. ./deploy.sh creates the venv on first run, copies bot.py and the unit file, reloads systemd and restarts the service. It never touches .env or alerts.db, so active alerts survive a deploy.

Failures & logs

09 · journalctl
SituationBehaviour
Binance WebSocket dropsReconnects with backoff (1 s doubling to 60 s), resubscribes, then checks the last ten 1m candles over REST for touches during the gap.
Binance's 24-hour disconnectSame as above; handled as a normal reconnect.
The bot process crashessystemd restarts it after 10 seconds. Active alerts reload from SQLite.
Pi rebootThe service starts at boot; alerts are still in the database.
Slow Binance reply on /alertThe command is acknowledged first ("thinking…"), so Discord's 3-second limit isn't hit.
Commands missing after a restartRe-registering can take ~30 s when Discord rate-limits; restarting Discord itself refreshes the menu.

Cost & security

10
  • No LLM. Slash commands arrive already split into a symbol field and a price field; there is nothing to interpret, so no AI tokens are used.
  • Free. Discord bots and Binance public market data cost nothing. The Pi was already running.
  • Read-only on Binance. No API key, no account, no way to trade.
  • Minimal Discord permissions. No privileged intents, three channel permissions, private application, mentions limited to the alert's owner.
  • One secret. The bot token, kept only in the Pi's .env (mode 600), not in code, git or this page.

Changelog & lessons

11
2026-10-11
shipFirst version: /alert, /alerts, /remove; kline_1m touch detection; SQLite storage; systemd service.
2026-10-11
bugREST catch-up could fire on a candle from before the alert existed.

After a reconnect the bot rechecks the last ten 1m candles. Older candles were treated like the creation minute and compared on their close. Now any candle that ended before the alert was created is skipped. Covered by seven offline cases for up/down, wicks, and the creation minute.

2026-10-11
bug"The application did not respond."

The Binance socket was stored as self.ws, which is the name discord.Client uses for its own gateway connection. Overwriting it crashed the bot a few seconds after start, systemd restarted it, and the cycle repeated, so commands landed while the bot was down. Renamed the attribute and made /alert acknowledge before calling Binance.

2026-10-11
lessonSubclassing a framework client means sharing its namespace.

Prefix your own attributes (binance_ws, not ws), and watch the restart counter (systemctl show -p NRestarts) after a deploy, not just "active".
